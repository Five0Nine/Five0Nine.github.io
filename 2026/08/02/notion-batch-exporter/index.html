Notion 批量导出 PDF：递归读取与高保真渲染

Notion 单页导出很方便，但面对多篇笔记和多层子页面时，逐个操作会很麻烦。

因此我做了一个本地命令行工具：Notion Batch Exporter。它通过 Notion 官方 API 读取已授权页面，将内容递归转换为 PDF，不需要浏览器 Cookie，也不会把私人笔记上传到第三方服务。

实现效果

工具支持：

  • 同时导出多个页面
  • 按标题搜索并多选
  • 递归导出所有普通子页面
  • 分别保存 PDF，或合并为一个文件
  • 保留封面、图标、颜色、Callout、多栏和表格
  • 浅色与深色主题
  • 生成 manifest.json，记录页面层级和导出警告

一次完整导出的处理流程是：

递归读取页面

Notion 的页面内容由 Block 组成。读取一个 Block 后，如果它还有子内容，就继续向下请求；遇到 child_page 时，则记录为下一轮需要读取的页面。

外层使用 ThreadPoolExecutor 同时读取同一层级的兄弟页面。为了避免并发请求过快，所有线程共用一个请求调度器，将请求起始速率控制在约每秒三次。

遇到 429 或临时服务器错误时，程序会读取 Retry-After 并自动退避重试。

还原 Notion 样式

直接使用轻量 PDF 库很难还原 Notion 的颜色、封面和多栏布局。因此高保真模式会先把页面 Block 转换成语义化 HTML，再通过 CSS 映射 Notion 的文字色和背景色。

最后使用 Playwright 调用 Chromium 的打印引擎：

这样可以利用浏览器成熟的排版能力，同时保留背景颜色、中文字体、多栏、表格和分页效果。如果本机没有 Chromium，工具也可以回退到 ReportLab 轻量渲染器。

输出与合并

每个页面会按照原有父子关系保存到对应目录，文件名附带页面 ID 前八位，避免同名笔记互相覆盖。

项目边界

工具只能读取明确授权给 Integration 的页面。为了避免意外导出大型数据库，child_database 不会被自动展开，需要手动选择其中的页面。

Notion API 也不会提供部分客户端视觉信息，例如封面焦点位置和原生图标 SVG，因此最终结果接近 Notion，但并不是客户端截图。

这个项目的重点不是完全复制 Notion，而是提供一种可批量、可审计、尽量保持原样，同时让私人笔记留在本机的导出方式。
