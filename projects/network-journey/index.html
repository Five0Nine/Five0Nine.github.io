  1. 客户端广播 DHCP Discover。
  2. 服务器依次完成 Offer、Request 与 ACK。
  3. 主机获得后续通信必需的四项网络参数。
固定追问

为什么主机还没有 IP 地址，也能发出 DHCP Discover？

DHCP 规定客户端可以暂用 0.0.0.0 作为源 IP，并通过广播寻找服务器，因此不要求预先拥有可正常单播的地址。

KNOWLEDGE BRANCHES

从主线伸出的专题

这些内容不强行塞进一次网页访问。展开后先看它接在哪个停靠点，再进入专题复习。

01 · 物理层计算 信道极限与编码 接入 STEP 08

围绕比特如何变成信号继续展开，不打断主流程中的逐跳传输。

  • 奈氏准则与码元种类
  • 香农定理与信噪比
  • 编码、调制与信道复用
02 · 链路可靠性 CRC、GBN 与 SR 接入 STEP 07 / 09

主线只展示 FCS 检错，可靠传输算法单独作为链路层专题比较。

  • 停止等待与超时重传
  • GBN、SR 的窗口约束
  • CRC 检错与海明码纠错
03 · 局域网扩展 WLAN、VLAN 与介质访问 接入 STEP 09

从交换机与当前链路继续比较共享介质、无线接入和广播域划分。

  • CSMA/CD 与二进制指数退避
  • CSMA/CA、DIFS、RTS/CTS
  • VLAN、Access 与 Trunk
04 · 路由控制平面 RIP、OSPF 与 BGP 接入 STEP 10

主流程使用的是已经生成的转发表；路由协议负责它如何被计算和更新。

  • 距离向量与链路状态
  • 自治系统内与自治系统间路由
  • 路由表、转发表与最长前缀匹配
05 · TCP 强化 窗口、重传与拥塞控制 接入 STEP 04

握手只是 TCP 的入口，后续专题集中处理序号、可靠传输和动态窗口。

  • 确认号、超时与快速重传
  • 接收窗口与流量控制
  • 慢开始、拥塞避免与快恢复
06 · 其他网络应用 FTP、邮件与 P2P 对照 STEP 05 / 12

用 HTTP 主线建立分层直觉后，再比较其他应用的连接方式与报文组织。

  • FTP 控制连接与数据连接
  • SMTP、POP3、IMAP 与 MIME
  • C/S 与 P2P 应用模型
